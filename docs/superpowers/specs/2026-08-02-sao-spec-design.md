# eソードアート・オンライン アリシゼーション-夜空- ロジック設計

正式機種名: eソードアート・オンライン アリシゼーション 夜空（シミュレーター表示名: SAOアリシゼーション夜空）

## スコープ

`logic.js`（純粋な確率・状態遷移ロジック・出玉換算・貸玉レート計算）と、node:testによるユニットテストのみを作成する。index.html/script.js/style.cssなどUI一式はフォーマット確定後に別途着手する。

## 台の基本スペック

| 項目 | 値 |
|---|---|
| 大当り確率（通常時） | 1/199.9 |
| 大当り確率（RUSH中：SR/WoU共通） | 1/51.6 |
| RUSH突入率 | 50% |
| SR（SWORD RUSH）継続率 | 約65% |
| WoU（War of Underworld）継続率 | 約75% |
| 時短回転数 | 0回 / 53回 / 70回 |

## ①通常時の抽選

毎回転 `1/199.9` でヒット判定。ヒット時は単発の累積バケット抽選で以下に分岐:

| 当選内容 | 割合 | 時短 | 移行先 | 公称払出 |
|---|---|---|---|---|
| ぼくの英雄 | 1.5% | 70回 | WoU直行 | ソードドライブ演出（先付け1500） |
| 2R（成功） | 48.5% | 53回 | SR突入 | 300個 |
| 2R（失敗） | 50.0% | 0回 | 通常継続 | 300個 |

## ②SR中の抽選

毎回転 `1/51.6` でヒット判定。ヒット時は単発の累積バケット抽選で以下に分岐:

| 当選内容 | 割合 | 時短 | 移行先 | 公称払出 |
|---|---|---|---|---|
| 10R（決意の刃なし） | 45.0% | 53回 | SR継続 | 1,500個 |
| 10R（決意の刃・失敗） | 33.0% | 53回 | SR継続 | 1,500個 |
| 10R（決意の刃・成功） | 11.0% | 70回 | WoU移行 | 1,500個 |
| 咲け、花たち（決意の刃・成功） | 11.0% | 70回 | WoU移行 | ソードドライブ演出（先付け1500） |

## ③WoU中の抽選

毎回転 `1/51.6` でヒット判定。ハズレ当り（時短なし）は存在しない。ヒット時は単発の累積バケット抽選で以下に分岐:

| 当選内容 | 割合 | 時短 | 公称払出 |
|---|---|---|---|
| 10R | 60.0% | 70回・WoU継続 | 1,500個 |
| 神器解放SWORD DRIVE | 40.0% | 70回・WoU継続 | ソードドライブ演出（先付けなし） |

## ④ソードドライブ演出（共通内部ロジック）

1,500個確定後、排他的に2ルートへ:

- **ルートA（97.5%）**: 保留4個を1個ずつ`1/2.17`で抽選。当選数0〜4個に応じて`先付け + 1500 + 1500×当選数`（当選数0でも1,500個保証、4個時は7,500個で確定）。
  - ※ユーザー提示の疑似コードは`先付け + 1500×当選数`だったが、④セクションの表（0個→1,500個〜4個→7,500個）およびSR/WoUのレンジ説明（WoU: 1,500〜7,500個、SR: 合計3,000〜9,000個）と整合させるため、`1500×(当選数+1)`が正として採用（ユーザー確認済み）。
- **ルートB（2.5%）**: 保留消化を経由せず、1.5%で`先付け+3000`確定、1.0%で`先付け + resolveSwordDrive(0)`（再帰でもう一回）。

## ⑤実獲得個数（公称払出からの換算）

払い出し出玉（公称払出）と実獲得出玉は一致しない。全てのボーナスは15球の集合体で、その15球を得るために1球消費する仕組みのため、**実獲得 = 公称払出 × 14/15**（約9%減）。

| 公称払出 | 実獲得 |
|---|---|
| 300個 | 280個 |
| 1,500個 | 1,400個 |
| 3,000個 | 2,800個 |

本仕様のボーナス単位（300・1500の倍数）はすべて15の倍数のため、`公称 - 公称/15`は常に整数で割り切れる。`applySpin`は`{ nominal, actual }`の両方を返す（ghoul版の`actualBalls`/`nominalBalls`二重管理と同じ考え方）。

## ⑥貸玉料金・回転数の対応

貸玉料金4円（250個あたり＝1000円で250個、等価）を基準に、割数ごとに実際の回転数が変わる。

| 貸玉料金 | 100円あたり | 回転数（1000円あたり） |
|---|---|---|
| 4.0円（等価） | 25個 | 20.0回転 |
| 3.5円 | 28個 | 21.0回転 |
| 3.3円 | 30個 | 21.6回転 |
| 3.0円 | 33個 | 22.5回転 |
| 2.5円 | 40個 | 24.4回転 |

各料金ごとの実際の回転数はホール公表値をそのままテーブルとして保持する（ghoul版の`calcSpinCost`のような単一の比例式では値が一致しないため、レートごとの実測値をルックアップする方式を採る）。1回転あたりの消費球数は`(1000 / 貸玉料金) / 回転数`で導出できる。

## アーキテクチャ

- `logic.js`: `'use strict'` + `module.exports`、ghoul版の規約を踏襲
  - 確率定数: `P_NORMAL_HIT = 1/199.9`, `P_RUSH_HIT = 1/51.6`
  - `spinNormal()` / `spinSr()` / `spinWou()`: ヒット判定→ヒット時のみtype抽選（ghoul版`rollRushHitType`と同じ「1回のhit判定→1回のtype抽選」パターン）
  - `resolveSwordDrive(precedingBonus)`: 再帰関数。ルートB分岐→さらに再帰、ルートA→保留4個ループ。戻り値は公称払出
  - `toActualBalls(nominal)`: `nominal * 14 / 15`で実獲得個数に換算
  - `applySpin(state)`: `{ mode: 'normal'|'sr'|'wou', jitanRemaining: number }` を受け取り、現在modeに応じたspin関数を呼び、新state・outcome種別・`{ nominal, actual }`払出を返すイミュータブルな遷移関数（ghoul版`applyRushSpin`と同型）
  - `RENTAL_RATE_TABLE` / `calcBallsPerSpin(yenPerBall)`: 貸玉料金ごとの回転数・消費球数のルックアップ
- `test/logic.test.js`: `withMockRandom`ヘルパー（ghoul版から移植）でMath.randomを固定し、各確率境界・状態遷移・ソードドライブの再帰分岐（ルートA全パターン、ルートB両分岐、再帰時の合算）を網羅
- `package.json`: `"test": "node --test \"test/**/*.test.js\""`（ghoul版と同一）
